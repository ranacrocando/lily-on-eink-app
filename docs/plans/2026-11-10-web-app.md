# Web app (M2) Implementation Plan

> **For agentic workers:** Use superpowers:subagent-driven-development. Each task is one PR (conventional-commit title given). Every PR is reviewed by an agent other than its author.

**Goal:** A static web app where a non-technical user drops LilyPond files, picks an e-reader and gets device-sized PDFs, all in the browser.

**Architecture:** Vite + TypeScript + plain DOM. The app imports `@lily-on-eink/core` (MIT) and `@lily-on-eink/engine-wasm` (GPL) from the sibling checkout `../lily-on-eink`. The engine (`@sightread/lilypond-wasm`) already runs every compile in its own module Web Worker, so `convert()` runs on the main thread: it only does string work and awaits the engine. This meets spec §7 ("compiles run in a Web Worker") without a second worker.

**Tech stack:** Vite, TypeScript (strict), Vitest (+ happy-dom for DOM units), ESLint flat config, fflate (MIT, ZIP), Playwright (Chromium) for smoke and parity tests.

**Spec:** `lily-on-eink/docs/specs/2026-11-09-lily-on-eink-design.md` §7, §9.7, §10.

## Conventions (all tasks)

- Conventional commits for commits and PR titles. Commits only as `ranacrocando` with the noreply address (per-folder git identity is already set up).
- Node 22 (`.nvmrc`). Exact versions in `package.json` (no `^`), as in the core repo.
- UI text in English, short and non-technical. No UI framework, no CSS framework. One `src/styles.css`.
- `localStorage` access always wrapped in try/catch; the app works without it.
- No network calls besides loading the app's own assets. No analytics, no fonts from CDNs.
- Each module gets unit tests for its logic; DOM wiring is covered by the Playwright smoke test (Task A5).
- `npm run build`, `npm run lint`, `npm run typecheck`, `npm test` must pass before every push. The local pre-push privacy hook must pass (Task A1 copies it from core).

## How the app gets the core (local and CI)

- `package.json`:
  ```json
  "dependencies": {
    "@lily-on-eink/core": "file:../lily-on-eink/packages/core",
    "@lily-on-eink/engine-wasm": "file:../lily-on-eink/packages/engine-wasm"
  },
  "overrides": { "@lily-on-eink/core": "$@lily-on-eink/core" }
  ```
  The `overrides` entry stops npm from looking up `@lily-on-eink/core@0.0.0` (engine-wasm's dependency) on the registry.
- `.npmrc`: `install-links=true`. npm then installs the two packages as real copies (from their `files: ["dist"]`), and `@sightread/lilypond-wasm` lands once in the app's own `node_modules`. Precondition: core is built (`npm ci && npm run build` in `../lily-on-eink`). After a core change: rebuild core, then `npm install` in the app.
  - Verify in A1: `npm ls @sightread/lilypond-wasm` shows exactly one copy, version 0.2.0. If `install-links` does not work with `npm ci`, fall back to `npm pack` of both core packages and `.tgz` dependencies (the same shape as the M3 release tarballs), and document the choice in the README.
- `core-ref.txt`: the core commit SHA the app is built against. CI checks out core at that ref (see A1). Bumping core = a PR that changes this file, runs `npm install` and commits the regenerated `package-lock.json` in the same PR.

## Engine loading in Vite

- `vite.config.ts`:
  - `base: process.env.APP_BASE ?? '/lily-on-eink-app/'` (`/` for a custom domain later).
  - `optimizeDeps: { exclude: ['@sightread/lilypond-wasm', '@lily-on-eink/engine-wasm'] }` so the `new URL('../dist/lilypond.wasm', import.meta.url)` and `new Worker(new URL('./worker.mjs', import.meta.url), { type: 'module' })` patterns are not broken by pre-bundling.
  - `worker: { format: 'es' }`.
  - Vite hashes asset names. A1 adds `scripts/check-build.mjs` (run in CI after `vite build`) that asserts `dist/assets` contains `lilypond-*.wasm`, `runtime.data-*.bin` and `lilypond-*.mjs` plus a worker chunk, exactly one `.wasm` above 10 MB, and a total `dist` size under 40 MB (catches a duplicated 15 MB asset).
  - The engine needs no cross-origin isolation (no SharedArrayBuffer), so GitHub Pages works without COOP/COEP headers.
- Multi-page build: `index.html` and `about.html` (`build.rollupOptions.input`).
- **Minimum browsers:** Chrome/Edge 116, Firefox 124, Safari 17.4 (`AbortSignal.any`, module workers, `DecompressionStream`). Documented in the README; A1 adds a startup feature check.
- **Deployment** (GitHub Pages workflow) is M3 work: Pages is not available for the private repo.

## Core-repo tasks (in `lily-on-eink`, separate PRs)

### Task C1: engine preload with download progress
PR title: `feat(engine-wasm): preload the engine with download progress`

- `packages/core/src/engine.ts`: add to `Engine`:
  ```ts
  /** Optional: load the engine ahead of the first compile. */
  preload?(options?: { signal?: AbortSignal; onProgress?: (p: { loadedBytes: number; totalBytes: number }) => void }): Promise<void>;
  ```
- `packages/engine-wasm/src/index.ts`: implement `preload` by creating the reusable compiler (same `compiler ??=` path) and calling `compiler.preload(options)`. Rejects after `dispose()`.
- Contract test in `packages/engine-wasm/test/contract.test.ts`: `preload()` resolves; a compile afterwards works. (`onProgress` may not fire in Node because assets are read from disk; do not assert on it.)

### Task C2: remaining device presets
PR title: `feat(core): add more e-reader presets`

- Add presets to `packages/core/src/presets/devices.json` with a `source` URL each (manufacturer spec page preferred). Candidates: Kobo Libra 2, Kobo Libra Colour, Kobo Clara 2E, Kobo Elipsa 2E, Kindle Paperwhite (2021 and 2024), Kindle Scribe, Kindle Oasis, PocketBook InkPad 4, PocketBook Era, Boox Note Air 3, reMarkable Paper Pro. Only add a device when resolution **and** ppi are confirmed by a source; list skipped ones in the PR body.
- `staffSizeAdjust`: −1 for screens under 7" diagonal, else 0 (same rule as kobo-clara-bw).
- Corpus compile tests: keep the matrix at the three M1 presets (runtime). Add one unit test that every preset has positive integer px, ppi between 150 and 400, and a non-empty source.

### Task C4: version warnings and shared file-name helper (before A2)
PR title: `feat(core): warn about old LilyPond versions`

- `analyzeProject` today returns only raw `versions`; the spec §5.2 thresholds are not implemented. Add `versionWarnings(versions: Record<string, string>): Diagnostic[]` in `project.ts` (exported): below 2.24 → warning "written for LilyPond <v>; may need convert-ly"; below 2.20 → a stronger warning with step-by-step guidance (install LilyPond, run `convert-ly -e file.ly`, upload again). No `\version` → no diagnostic. `convert()` appends these to its diagnostics.
- Export the FAT32 sanitizer from `outputs.ts` as `safeFileName(name: string): string` (reuse the existing `clean` + trim logic), so the app does not duplicate it.
- Update the spec: §3 diagram and §7 say core runs on the main thread and the engine runs compiles in its own Web Worker.
- Unit tests for both functions.

### Task C3: calibration page source
PR title: `feat(core): add a calibration page for a device`

- New `packages/core/src/calibration.ts`, exported from `index.ts`: `calibrationSource(device: DeviceSpec, lilypondVersion: string): string` returns a standalone `.ly` (no wrapper, no user file) with:
  - paper = full device size, all margins 0, no header/footer/tagline;
  - a 0.3 mm border exactly on the page edge, tick marks every 1 mm along all four edges (5 mm ticks longer, labelled every 10 mm), a light 10 mm grid, and centred text with the device name, size in mm/px and ppi.
  - Written from scratch with `\markup` drawing commands (`\draw-line`, `\filled-box`, `\translate`, `\with-dimensions`), MIT, no copying from LilyPond's `.ly` init files.
- Test (in `packages/engine-wasm/test/`, because core tests must not import the GPL package): compile via engine-wasm in Node for kobo-sage; PDF page size equals the device size (±0.5 mm, reuse the corpus test helper); PNG has dark pixels within 1 px of each page edge.

## App-repo tasks (in `lily-on-eink-app`)

### Task A1: scaffold, engine smoke page, CI
PR title: `feat: scaffold the web app`

Files: `package.json`, `package-lock.json`, `.npmrc`, `.nvmrc` (22), `.gitignore` (`node_modules`, `dist`, `test-results`, `playwright-report`, `public/licenses`, `.privacy-denylist`), `scripts/check-build.mjs`, `src/support.ts`, `tsconfig.json`, `vite.config.ts`, `vitest.config.ts`, `eslint.config.js`, `index.html`, `src/main.ts`, `src/engine.ts`, `src/styles.css`, `core-ref.txt`, `scripts/privacy-check.mjs` + `.githooks/pre-push` (copied from core; `prepare` script sets `core.hooksPath`), `.github/workflows/ci.yml`, `.github/workflows/pr-checks.yml`, `.github/pull_request_template.md`, `REUSE.toml` (all GPL-3.0-or-later), this plan, README update.

- `src/engine.ts`: a singleton `getEngine()` around `createWasmEngine()`, plus `loadEngine(onProgress)` calling `engine.preload?.(...)`. Depends on C1; until C1 is merged, `loadEngine` falls back to `engine.lilypondVersion()` without progress (indeterminate bar).
- `index.html` + `src/main.ts`: page title "lily-on-eink", a short intro line, an engine status area with a `<progress>` bar ("Loading the music engine (30 MB, once)…"), then "Preparing…" once the download is complete (the version check is a full LilyPond run), then "Ready – LilyPond 2.26.0".
- `src/support.ts`: startup feature check (`AbortSignal.any`, `DecompressionStream`, `WebAssembly`, module `Worker`); if one is missing, show only "Please update your browser" with the minimum versions. Unit-tested with stubbed globals.
- Scripts: `dev`, `build` (`tsc --noEmit && vite build`), `preview`, `lint`, `typecheck`, `test` (vitest), `privacy`.
- CI (`ci.yml`), mirroring core: triggers `pull_request` and push to `main`, same concurrency group, `permissions: contents: read`. Steps:
  1. checkout app to `lily-on-eink-app`, `persist-credentials: false`;
  2. read `core-ref.txt`; checkout `ranacrocando/lily-on-eink` at that ref to `lily-on-eink` with `token: ${{ secrets.CORE_REPO_TOKEN }}`, `persist-credentials: false`;
  3. setup-node from `.nvmrc`, npm cache keyed on both lockfiles;
  4. core: `npm ci && npm run build`; app: `npm ci`, `npm run lint`, `npm run typecheck`, `npm test`, `npm run build`, `node scripts/check-build.mjs`.
  - One job only. A7 adds the Playwright steps to this job (spec §10: "build plus Playwright smoke").
- `pr-checks.yml`: identical to core's (PR title check).
- Manual check (report in PR): both `npm run dev` and `npm run build && npm run preview`: open the page, engine loads, version shows. Dev serves `lilypond.mjs` through Vite's transform pipeline, so both must be checked.

### Task A2: file input and project analysis
PR title (A2–A4 together): `feat: convert uploaded LilyPond files for a device`

- `src/files.ts`:
  - `fromFileList(files: FileList | File[]): Promise<ProjectFile[]>` using `webkitRelativePath || name`.
  - `fromDataTransfer(dt: DataTransfer): Promise<ProjectFile[]>` walking `webkitGetAsEntry()` directories recursively (`readEntries` must be called until it returns an empty batch).
  - Keep only `.ly` and `.ily` files (core only scans these); skip hidden files/dirs (`.` prefix) and files over 2 MB (report skipped names). POSIX paths, no leading `/`.
  - If every path shares one top-level folder, keep it (includes stay relative anyway).
- `analyzeProject(files: Record<path, string>, builtins?)` takes text, so `files.ts` also decodes sources as UTF-8 into that record (and keeps `ProjectFile[]` for `convert()`).
- `src/project-panel.ts`: renders `analyzeProject()` from core: main files as checkboxes (all checked by default), missing includes with the text "`<file>` includes `<target>`, which was not uploaded. Add the file or the whole folder.", and `versionWarnings(analysis.versions)` (C4).
- UI: a drop zone (click opens a file picker; a second button "Choose a folder" uses `webkitdirectory`). Re-dropping replaces the project.
- Tests (happy-dom): path normalization, filtering, top-level folder handling, a fake `FileSystemDirectoryEntry` tree with `readEntries` returning two batches.

### Task A3: settings
- `src/settings.ts`: `{ deviceId: string | 'custom'; custom: { widthPx, heightPx, ppi }; profileId: string; noteSizeDelta: number }`, load/save in `localStorage` key `lily-on-eink:settings:v1`, try/catch, validated on load (unknown device id → `kobo-sage`).
- Device `<select>` from `listDevices()` plus "Custom size…". Custom inputs: width/height px 300–4000, ppi 100–600; builds a `DeviceSpec` `{ id: 'custom', name: 'Custom <w>×<h>', safeAreaMm all 0, staffSizeAdjust: 0, source: 'user' }`.
- Profile `<select>` from `listProfiles()`.
- Note size slider −3…+3 (step 1), label shows the resulting staff size `effectiveStaffSize(profile, device) + delta`; passed as `staffSize` only when delta ≠ 0.
- Show the page size in mm (`pageSizeMm`).
- Tests: load/save round trip, broken JSON, storage throwing, custom spec validation.

### Task A4: convert, progress, cancel, download
- `src/convert-run.ts`: calls core `convert(files, { device, profile, staffSize, mainFiles, outputs: ['pdf'], signal, timeoutMs: 60000, onProgress }, getEngine())`.
- Progress text "Converting 2 of 5: song.ly"; a Cancel button aborts via `AbortController`. 
- Cancel or timeout terminates the engine's worker; the next compile would silently reload the 30 MB engine (from the HTTP cache) and recompile the WASM. So after a cancel or timeout, call `loadEngine(onProgress)` again and show the engine status bar until it is ready.
- Results list: one row per output with file name and a Download button; diagnostics: `ConvertResult.diagnostics` is one flat list and errors often point at an included `.ily`, so show all diagnostics (severity, message, file:line) in one list, plus per failed main file a "Show LilyPond log" `<details>` with `logs[mainFile]`. (`Diagnostic` has severities `error`/`warning` and no `code` field.)
- `src/download.ts`: `downloadBlob(name, bytes, type)`; "Download all (ZIP)" when there is more than one PDF, built with `fflate.zipSync` (store, no compression: PDFs are already compressed). ZIP name `lily-on-eink – <device name>.zip`, made FAT32-safe with core's `safeFileName` (C4). Duplicate output names (two files with the same title) are deduplicated as `name (2).pdf` before zipping.
- Tests: zip contains the expected names; duplicate-name dedupe; convert-run with a fake `Engine` (success, failure with diagnostics, abort triggers an engine reload).

### Task A5: preview (own PR)
PR title: `feat: preview the first page in e-ink greys`

- After a successful conversion, compile the first output's main file again with `outputs: ['png']` only when the user opens the preview (lazy, avoids doubling the default compile time). Use `pngPages[0]`.
- `src/preview.ts`: decode PNG via `createImageBitmap`, draw to a canvas, convert to luminance and quantize to 16 grey levels (`Math.round(l / 255 * 15) * 17`). Pure function `quantize16(data: Uint8ClampedArray)` unit-tested.
- Shown inside a frame with the device's aspect ratio (CSS `aspect-ratio: w / h`), scaled to fit the viewport.

### Task A6: About/licenses page, transfer help, calibration (own PR)
PR title: `feat: add about page, transfer help and calibration page`

- `scripts/copy-licenses.mjs` (run by `prebuild` and `predev`): copies `node_modules/@sightread/lilypond-wasm/licenses/*` (includes `THIRD-PARTY-NOTICES.txt`) plus the `LICENSE` of every runtime dependency in the bundle (`@lily-on-eink/core` MIT, `@lily-on-eink/engine-wasm` GPL, `fflate` MIT; derive the list from `dependencies` in `package.json` so a new one is not missed) into `public/licenses/` (git-ignored) and writes `public/licenses/index.json` with the file list.
- `about.html` + `src/about.ts`: GPL-3.0-or-later notice for the app, the list of third-party notices (links to the copied files, not restated), the LilyPond version, a "Source code" link (repo URL; corresponding-source release asset link added at M3), and the privacy statement "Your files never leave your browser."
- Transfer help (`src/help.ts`, per device family by id prefix): Kobo (USB, copy to the reader's drive), Kindle (USB to `documents/`; Send-to-Kindle converts PDFs badly, so use USB), PocketBook (USB or Send-to-PocketBook email), reMarkable (desktop/mobile app or USB web interface), Boox/custom (USB). Shown under the results.
- "Download calibration page" button (needs C3): compiles `calibrationSource(device, version)` directly through the engine and downloads `Calibration – <device name>.pdf`, with a one-paragraph explanation of how to check the visible edge.

### Task A7: Playwright smoke and parity (own PR)
PR title: `test: add browser smoke and parity tests`

- Timeouts: the cold path is engine download + WASM compile + version compile + score compile. `test.setTimeout(180_000)`, and `{ timeout: 120_000 }` on the "Ready" and result assertions. `webServer.url` includes the base: `http://localhost:4173/lily-on-eink-app/`.
- `test/e2e/smoke.spec.ts`: `vite preview` as `webServer`; load the page, wait for "Ready", upload `test/fixtures/bass-etude-e-minor/*.ly` (copied from the core corpus, CC0, with its license note), choose kobo-sage, convert, assert one result, click Download and check the downloaded file starts with `%PDF` and has the expected name.
- `test/e2e/parity.spec.ts`: in the browser, convert the same fixture to PNG (expose a test hook `window.__lilyOnEink.convertPng(files, settings)` only when the page is opened with a `?test` query, so the tests run against the build that ships; documented). In the Node test process, run core `convert()` with `createWasmEngine()` on the same input and `dispose()` the engine afterwards. Assert both first-page PNGs are byte-identical, or decode both (pngjs) and allow ≤ 0.01% differing pixels.
- The fixture gets its own entry in `REUSE.toml` (CC0) and its license note.
- CI: extra steps in the existing `check` job (no second job repeating the core checkout): `npx playwright install --with-deps chromium`, `npx playwright test`, upload `playwright-report` on failure. Job timeout 20 min.
